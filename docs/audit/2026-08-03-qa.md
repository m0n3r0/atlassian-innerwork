### 1.1 Modules below 60%: only `cli.py` — and why the 0% is a measurement artifact

`cli.py` reports 0% under pytest-cov, but the CLI *is* exercised: every CLI test
(`test_cli.py`, `test_domain_cli.py`, `test_cli_serve.py`, `test_migration.py`,
`test_markdown_importer.py`) invokes the CLI via `subprocess.run([sys.executable,
"-m", "innerwork.cli", ...])`. pytest-cov does not instrument subprocesses, so
none of that execution is measured. The honest reading:

- **Subcommands exercised via subprocess tests**: `catalog`, `validate`,
  `render` (happy path only), `serve` (dry-run only), `workflow`, `projects`,
  `project-create`, `work-item-create`, `work-item-transition`, `export`,
  `import`, `migrate`, `metrics`, `import-markdown` (incl. CLI error exit 2).
- **CLI wiring with no test at all**: `products` and `phases` subcommands
  (`catalog.product_catalog()` is unit-tested in-process via the `/v2/catalog`
  broker endpoint, but `catalog.production_oss_phases()` has **zero in-process
  coverage** — `catalog.py:36` is never executed; its only callers are the
  untested `cli.py:190` branch and the untested `app.py:204` endpoint — and the
  `main()` dispatch branches at `cli.py:186–191` are never run); `render`
  failure path (`cli.py:201–203`, operation state != succeeded → exit 1);
  `_resolve_database_url` non-`sqlite:///` rejection (`cli.py:282–284`);
  `import` unreadable-file OSError (`cli.py:364–366`);
  no `--help` / no-args / unknown-command tests.
- **Structural weakness**: because the CLI is only tested out-of-process, its
  coverage is permanently invisible to the coverage gate, each test pays a full
  interpreter boot, and error paths can only be asserted via returncode/stderr,
  never by catching exceptions in-process. Suggested fix: add in-process tests
  for `build_parser()` + `main(argv)` (parse errors, unknown commands, the
  `products`/`phases`/`render`-failure branches) while keeping the subprocess
  tests as end-to-end smoke; optionally wire `COVERAGE_PROCESS_START` +
  `parallel=true` so subprocess runs are measured too.

  pyright clean — typed `_event` helper + pyright extraPaths"* — 5
  `reportArgumentType` errors and 2 `reportMissingImports` errors, all in

  Verified green at audit time (0 errors).

### 3.3 Guardrail fix `2ea7180` (.worktrees skip) — **no regression test**

- What happened: `scripts/check_anti_hallucination.py` false-positived on
  allowlisted files under `.worktrees/*` paths when the scan ran from a main
  checkout with linked worktrees. Fix added `.worktrees` to `SKIP_DIRS`.
- Is there a test that would catch a future regression? **No.** The existing
  `test_anti_hallucination_script_passes`
  (`tests/test_threat_model_and_guardrail.py:28–40`) runs the script against
  `REPO_ROOT` — in CI that is a fresh checkout with no `.worktrees/` directory,
  and in a local worktree the `.worktrees/` directory is a *parent* sibling of
  the scan root, so the `SKIP_DIRS` entry is never exercised either way.
  `test_anti_hallucination_detects_forbidden_term` is a positive control only.
- Suggested fix (Medium): add a regression test that builds a `tmp_path` tree
  containing a forbidden token *under a `.worktrees/` subdirectory* and asserts
  exit code 0 (directory is skipped), plus a control asserting the same token in
  a normal directory trips the scan (already covered by the existing positive
  test). This pins the 2ea7180 behavior.

## 4. Test quality

- **No mocks anywhere.** `grep -r "monkeypatch|unittest.mock|Mock(" tests/`
  returns zero hits. The suite exercises real `DomainStore` instances over
  temp-file SQLite / in-memory stores and real `TestClient` requests. No
  over-mocking problem exists.
- **No flaky patterns.** No `time.sleep`, no real network, no `random`, no
  `datetime.now`/`utcnow` dependence in tests. `uuid4()` appears only to mint
  opaque idempotency keys; assertions never depend on the value.
- **No vacuous tests.** No `assert True`, `pass`-bodied tests, `skip`, or
  `xfail` in the suite (332 tests, all asserted).
- **No white-box implementation-detail assertions.** No test reads private
  attributes (`._store`, `._events`, ...). Assertions target API responses and
  observable behavior.
- **Weak spots:**
  - *Subprocess-based CLI tests* (§1.1): slow (suite is 68.7s; much of it is
    interpreter boot), unmeasurable by the coverage gate, error paths asserted
    only via returncode/stderr.
  - *`test_packaging.py` builds a wheel and pip-installs it* — a genuine
    end-to-end check of the packaged-resource fallback, but the slowest test in
    the suite and environment-dependent (`shutil.which("uv")` is asserted).
  - *Docs-presence tests* (`test_docker_poc_docs.py`, `test_production_oss_phases.py`,
    `test_product_catalog.py`) assert string presence in docs/data files — they
    are intentional content guards (anti-hallucination policy), not code
    exercise; they will need updating on every deliberate doc change.
  - *`test_cli_serve.py`* covers only `--dry-run`; the real uvicorn spawn path
    is untested by design (would bind a port).
  - *`test_app.py::test_create_app_is_reexported_from_innerwork_app_module`*
    is a smoke/import test (`assert callable(create_app)`) — weak alone, but it
    is exactly the class of test that catches the PR #14 import-incident
    recurrence, so it earns its place.

## 6. Summary and recommendations

Overall: **84% measured coverage, 332/332 tests passing, zero mocks, zero flaky
patterns, and genuinely strong portability/idempotency/error-path coverage in
the migration surface.** The audit found no fabricated gaps — every item below
is tied to a concrete uncovered line or a `grep` result.

Priority fixes (by leverage):

1. **[High] `ai_context.py` permission-filter + page-comment paths** (407–423,
   511–522) — the only security-adjacent surface with zero coverage.
2. **[High] `/v2/products` + `/v2/production-oss-phases` endpoints** — public
   HTTP surface with no test; also the `products`/`phases` CLI branches.
3. **[Medium] Guardrail `.worktrees` regression test** (pins 2ea7180) — the one
   incident fix with no test that could catch its recurrence.
4. **[Medium] Audit-sink query filters** (280–287, 390–414) and portability
   audit emission (204–205) — audit read-back is the trust surface from Phase 7.
5. **[Medium] Per-endpoint error branches in `domain_api.py`** (~76 lines) —
   table-driven 404/400 tests per endpoint family.
6. **[Low] In-process CLI tests** for `products`/`phases`/`render`-failure and
   parser errors; optionally measure subprocess coverage via
   `COVERAGE_PROCESS_START`.
7. **[Low] markdown `created_at` validation, model/domain validator edges.**
